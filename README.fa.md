# استانداردهای پروژه

**فارسی** · [English](README.md)

اسکلت مستنداتی که در هر مخزن می‌گذارم، تا پروژه خودش را برای یک غریبه، برای «خودمِ بعدی» و برای
یک ایجنت توضیح بدهد — بدون تکیه بر تاریخچهٔ چت یا یک ماشین خاص.

دلیل وجودش یک شکست واقعی است: همان کد یک جا راحت بود و جای دیگر عذاب‌آور، نه چون کد عوض شده بود،
بلکه چون یک ماشین واقعیت‌های پروژه را داخل ریپو داشت و دیگری فقط در یک مکالمه. تاریخچهٔ چت جابه‌جا
نمی‌شود؛ فایل و اسکیل جابه‌جا می‌شوند.

## در یک نگاه

| | |
|---|---|
| چیست | اسکلت مستندات (دو README، `AGENTS.md`، `HANDOFF.md`، `OPEN-ITEMS.md`، `DECISIONS.md`) |
| برای | هر مخزنی از من، روی هر ماشین، با یا بدون ایجنت |
| گیت | `python3 scripts/check-docs.py .` — شکل و رمز را می‌سنجد، نه درستی را |

## چه چیزی اینجاست

| مسیر | چیست |
|---|---|
| `templates/README.en.md` | صفحهٔ اول انگلیسی: چیست، چرا، چطور سرهم می‌شود، چطور اجرا می‌شود، چطور مطمئن شویم کار می‌کند |
| `templates/README.fa.md` | نسخهٔ فارسی با همان بخش‌ها — نه خلاصهٔ فشردهٔ نسخهٔ انگلیسی |
| `templates/AGENTS.md` | نقطهٔ ورود برای AI: نقشهٔ فایل‌ها، قاعده‌های سخت، «چطور چیزی اضافه کنم» (حدود ۶۰ خط) |
| `templates/HANDOFF.md` | وضعیت فعلی، تغییر آخر، تصمیم‌های زنده (حدود ۴۰ خط، عمداً کوتاه) |
| `templates/OPEN-ITEMS.md` | چک‌لیست کارهای باز با هزینهٔ `S`/`M`/`L`، از ارزان به گران، دام‌ها در آخر |
| `templates/DECISIONS.md` | تصمیم‌های تاریخ‌دار با دلیل و گزینه‌هایی که رد شدند |
| `templates/ARCHITECTURE.md` | چرا هر تکه وجود دارد — فقط وقتی سؤال به آن نیاز دارد |
| `checklists/new-project.md` | هشت قدم از مخزن خالی تا مخزن مستند |
| `checklists/release.md` | قبل از بیرون رفتن یک نسخه چه چیزهایی باید درست باشد |
| `scripts/new-project.sh` | قالب‌ها را در یک مخزن کپی می‌کند و نام پروژه را می‌گذارد |
| `scripts/check-docs.py` | گیت: هر دو README، لینک سوییچ، بخش‌های لازم، و نبود رمز |

## قاعده‌های پشت این فایل‌ها

۱. **دو زبان، دو فایل.** `README.md` انگلیسی است — چیزی که بازدیدکننده پیش‌فرض می‌بیند.
`README.fa.md` نسخهٔ کامل فارسی است، نه خلاصه. یک فایلِ دوزبانه هم‌زمان‌سازی راحت‌تری دارد ولی
خواندنش کندتر است و طولش دو برابر می‌شود؛ دو فایل یک گیت هم‌زمان‌سازی می‌خواهد که
`check-docs.py` ارزانش می‌کند.

۲. **README به پنج سؤال، به همین ترتیب، جواب می‌دهد:** این چیست، چرا وجود دارد، چطور ساخته شده،
چطور اجرا می‌شود، از کجا بفهمم هنوز کار می‌کند. وقتی جواب یک شکل است، نمودار قبل از متن می‌آید.

۳. **هر ادعا قابل بررسی است.** «production-ready» و «مقیاس‌پذیر» ممنوع؛ به‌جایش شمارهٔ نسخه،
دستور، عددِ اندازه‌گیری‌شده. اگر وضعیتی معلوم نیست، همان «معلوم نیست» نوشته می‌شود.

۴. **`AGENTS.md` نقشه است، نه کتابچه.** فایل‌ها و قاعده‌ها را نام می‌برد و می‌گوید «فقط همان فایلی
را باز کن که کار نامش را می‌برد». فایل ۴۰۰ خطی مرور می‌شود؛ فایل ۶۰ خطی رعایت می‌شود.

۵. **`HANDOFF.md` کوتاه می‌ماند.** تغییر آخر به‌علاوهٔ تصمیم‌های زنده. وقتی از حدود ۱۰۰ خط گذشت،
بخش‌های قدیمی‌تر به `docs/HISTORY.md` می‌روند. هندآف‌ای که لاگ شده، دیگر هندآف نیست.

۶. **تصمیم، دلیل و گزینهٔ ردشده را با خود دارد.** «X را انتخاب کردم» یک واقعیت است که دعوا را
برمی‌گرداند؛ «X را چون Y، نه Z چون W» دعوا را تمام می‌کند.

۷. **فهرست کارهای باز، چک‌لیست است نه متن**، از ارزان به گران، و هر آیتم یک خط «یعنی چه» دارد —
تصمیم روی معنی گرفته می‌شود، نه روی نام فایل.

۸. **تصویر و نمودار داخل مخزن می‌مانند.** اسکرین‌شات‌ها در `docs/images/` (بهینه، WebP)، و هر چیزی
که جریان است با Mermaid. نموداری که روی گیت‌هاب رندر می‌شود و کنار کد زندگی می‌کند، به‌روز می‌شود؛
عکسی که روی دسکتاپ کسی مانده، نمی‌شود.

## اجرا

```bash
git clone https://github.com/mmallaki/project-standards /tmp/standards
/tmp/standards/scripts/new-project.sh my-project ~/projects/my-project
cd ~/projects/my-project && python3 /tmp/standards/scripts/check-docs.py .
```

اسکریپت هیچ فایل موجودی را بازنویسی نمی‌کند؛ فقط چیزهای غایب را کپی می‌کند و می‌گوید چه چیزی را
رد کرده است.

## بررسی

`scripts/check-docs.py` وقتی شکست می‌خورد که مخزنی ادعا کند این استاندارد را دارد ولی ندارد:

- نبودِ `README.md` یا `README.fa.md`، یا نبودِ لینک سوییچ در یکی از آن‌ها
- نبودِ یک بخش لازم (چیست / اجرا / بررسی)
- بلوک Mermaid که باز شده و بسته نشده
- `TODO` در تیتر، یا بلوک کد خالی
- رشته‌ای که شبیه رمز است (`password = "…"`، `ghp_…`، `sk-…`) در هر متنِ ردیابی‌شده

این گیت عمداً سطحی است: وجود و شکل را می‌سنجد، نه درستی را. درستی کار بازبین است.
